Latency { Clocks & percentiles }

In-process stage timings via steady_clock, collected in latency_stats.hpp, printed at shutdown — not wire RTT.

01

steady_clock vs system_clock

ClockPropertyUse here
steady_clock Monotonic; safe for intervals All pipeline samples
system_clock Wall time; can jump (NTP) Not used for deltas

Deltas: duration_cast<nanoseconds>(t1 - t0).count() → int64_t into LatencyStats::add_ns.

Important

Do not mix clocks in one subtraction. Everything timed here is local to one process.

02

Three metrics (shipped names)

FieldDefinitionSampled
queue_wait match_started_at - enqueued_at Once per order (matcher)
match_duration matched_at - match_started_at Once per order (matcher)
match_to_publish published_at - matched_at Once per published event (publisher)

enqueued_at is set in MultiSymbolPipeline::run just before try_push. match_started_at / matched_at wrap engine.submit in matcher_worker.hpp.

Dropped ingress orders never reach the matcher → no queue_wait / match_duration sample. Drop counters are separate (Concurrency).

03

Where in this codebase

matcher_worker.hpp (per order)
const auto match_started_at = clock::now();
auto produced = engine.submit(go.request);
const auto matched_at = clock::now();

stats->queue_wait.add_ns(/* match_started_at - go.enqueued_at */);
stats->match_duration.add_ns(/* matched_at - match_started_at */);
// then push PublishEvent{…, enqueued_at, match_started_at, matched_at}
publisher.hpp (per event)
const auto published_at = steady_clock::now();
stats->match_to_publish.add_ns(
    duration_cast<nanoseconds>(published_at - pe.matched_at).count());
Type / fileRole
GatewayOrder::enqueued_atIngress stamp
PublishEvent timestampsCarry match timing to publisher
PipelineStats in latency_stats.hppThree LatencyStats + report_all()
MultiSymbolPipeline::stats()Owned by pipeline; mutex inside add_ns
src/main.cppPrints stats().report_all() after run

Sampling choice

Queue/match once per order so Accept+Trade does not double-count. Publish once per event because each event crosses the event queue separately.

04

p50 / p99

LatencyStats::report copies samples under a mutex, sorts, interpolates percentiles, prints µs. Same habit as TCP MDS: means lie on skewed distributions; report the tail.

  • p50 — typical healthy path
  • p99 — scheduler / CV / logging spikes
  • Also min / max / n
05

Reporting

Event lines from lob::format_event stay timestamp-free (LOB golden habit). Latency is a separate channel after the run:

CLI output shape
---- latency (steady_clock, in-process) ----
queue_wait: n=… p50=…µs p99=…µs min=… max=…
match_duration: …
match_to_publish: …

Echoing every event to stdout (echo_stdout=true) can inflate match_to_publish. Tests use echo_stdout=false.

06

Pitfalls

✕

Calling these “wire latency”

All stages are in-process. Say “pipeline stage latency.”

✕

Logging on the timed path

Per-order cout dominates the sample. Mute echo when quoting numbers; prefer Release.

✕

Mixing match duration with event push

This code stamps matched_at before event enqueue, so match duration is LOB-only. Keep it that way.

07

Decision

Decision

steady_clock + PipelineStats for queue_wait, match_duration, match_to_publish; p50/p99 at shutdown. Rejected: wall-clock deltas, wire/RTT claims, timestamps in event goldens.
