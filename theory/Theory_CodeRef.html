04

Threads & synchronization cheat sheet

std::thread

  • Joinable until join or detach — prefer join + RAII guard.
  • Destructor of a still-joinable thread calls std::terminate — why ThreadGuard exists.
  • Pass ids/indices by value into the thread body; do not capture loop variables by reference without care.
spawn pattern
std::vector<std::thread> workers;
for (int i = 0; i < n; ++i) {
    workers.emplace_back([i, &shards, &running] {
        matcher_loop(shards[i], running);
    });
}
// ThreadGuard or explicit join loop at shutdown

Mutex, unique_lock, condition_variable

  • lock_guard — scope lock, no CV.
  • unique_lock — unlockable; required for cv.wait.
  • Always wait with a predicate: cv.wait(lk, [&]{ return !empty || !running; }); — spurious wakeups are real.
  • notify_one for SPSC is enough; notify_all on shutdown.

Atomics & memory order

UseTypical orderNotes
Drop counters relaxed No synchronization story beyond the count

v1 simplicity

Default sequential consistency on atomics is fine for flags until you have a measured reason to weaken. Prefer correct + clear.

ToolRole in gateway
std::move Enqueue/dequeue orders without copies; transfer into LOB submit
Move-only types / = delete copy Optional on Order wrappers if you want the compiler to catch accidental copies
std::unique_ptr<T> Exclusive heap ownership when an order/event must outlive a stack frame — hand off, do not share
ThreadGuard Join in destructor (Rule of Five/Zero around the thread handle)
noexcept moves Helpful for containers; prefer on queue element moves
hand-off, not share
// producer
q.try_push(std::move(order));   // order is moved-from

// consumer
Order o;
if (q.pop(o)) {
    engine.submit(std::move(o));
}

06

Templates & lambdas

Queue template

API shape
template <typename T, std::size_t N>
class SpscQueue {
public:
    bool try_push(T&& item);
    void push(T&& item);          // may block
    bool try_pop(T& out);
    bool pop(T& out);             // may block until item or shutdown
    // …
};

Non-type template parameter N freezes capacity. Alternative: runtime capacity in the ctor — pick one and document it.

Lambdas as thread entry

  • [&] — easy and dangerous if the lambda outlives locals; prefer capturing what you need.
  • [=] — copies; fine for small ids; will not see later flag updates unless atomic/shared.
  • Do not capture this carelessly if the object dies before join.
✕

Capturing the loop variable by reference

for (int i=0; …) threads.emplace_back([&]{ use(i); }) — all threads may see the final i. Capture i by value: [i, &shards].

chrono, optional, enum class

chrono

  • using clock = std::chrono::steady_clock;
  • clock::now(), duration_cast<nanoseconds>, .count()
  • See Latency & Clocks for metric definitions.

std::optional

optional at boundaries
std::optional<Order> parse_line(std::string_view line);
// …
if (auto o = parse_line(line)) {
    route(std::move(*o));
}

enum class

Carry from LOB: side, order type, event kind, reject / cancel reasons. Wire publisher formatting through explicit casts or helpers — never rely on plain enums promoting to int in logs accidentally.

09

Deliberately unused in v1

Useful to know what this project is not demonstrating (even if sibling repos do):

  • std::shared_ptr for live orders across threads — hand-off with move / unique_ptr instead
  • Lock-free atomic rings, hazard pointers, memory-order olympics on the queue data path
  • Networking: socket, poll, epoll, MDS framing headers
  • std::jthread as a hard requirement (C++20) — optional later; RAII join is enough
  • Thread pools / work stealing across symbols
  • Exceptions for full-queue control flow
  • Boost.Asio, Folly, lock-free third-party queues

Q C++17 vs MDS C++11 — why diverge?

MDS stayed on C++11 for a tight sockets story. This repo’s curriculum is threads and modern library types; C++17 is the intentional floor.
