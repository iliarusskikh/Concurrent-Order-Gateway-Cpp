Ownership { Move, RAII & language }

How orders, shards, and threads are owned in this tree — move hand-off through SPSC queues, RAII joins, unique_ptr<Shard>, and the templates/lambdas that wire the pipeline.

01

Move hand-off across queues

GatewayOrder (gateway_order.hpp) is the ingress message: symbol id, LOB request, enqueue timestamp. At every hop there should be one clear owner — gateway local → ring slot → matcher local → outbound PublishEvent.

gateway_order.hpp · make + push
// gateway stamps time, then moves into the shard ingress
GatewayOrder go = src;
go.enqueued_at = std::chrono::steady_clock::now();

Shard& shard = *shards_[go.symbol_id];
if (!shard.ingress.try_push(std::move(go))) {
  ingress_drops_.fetch_add(1, std::memory_order_relaxed);
}
// after a successful push, do not touch go

SpscQueue::try_push(T&&) moves into the ring; try_pop / pop_wait move out into the caller’s local. Prefer std::move even when the payload is POD — the habit documents exclusive hand-off and stays correct if the type grows later.

Decision

Value types on the hot path, moved hop-to-hop. Rejected: shared_ptr<GatewayOrder> through the queue — shared mutable ownership fights the SPSC “one producer / one consumer” story and adds atomic refcount traffic for no gain.

02

Why copy is deleted on queue types

An SpscQueue owns a ring, a mutex, and two condition variables. Copying it would duplicate synchronization state while two threads still believe they share one buffer — undefined and meaningless.

spsc_queue.hpp · non-copyable
template <typename T, std::size_t N>
class SpscQueue {
public:
  SpscQueue() = default;

  // Queues are shared between two threads by *reference*.
  // Copying would duplicate mutex/CV/ring state incorrectly.
  SpscQueue(const SpscQueue&) = delete;
  SpscQueue& operator=(const SpscQueue&) = delete;

  bool try_push(T&& item);
  bool try_pop(T& out);
  // ...
};

The pipeline never relocates a live queue after workers start. Threads hold references into pipeline-owned storage; the type itself stays put. That is also why Shard (which embeds two queues) is not movable — see §04.

  • Push: move from caller into a slot; caller drops ownership.
  • Pop: move from slot into caller storage; then advance head.
  • Do not return const T& into a ring slot across threads.
03

ThreadGuard — RAII and the Rule of Five

Destroying a still-joinable std::thread calls std::terminate. ThreadGuard (thread_guard.hpp) owns one thread and joins in reset() / the destructor so stack unwinding and early returns stay safe.

thread_guard.hpp · special members
class ThreadGuard {
public:
  ThreadGuard() noexcept = default;
  explicit ThreadGuard(std::thread&& t) noexcept : t_(std::move(t)) {}
  ~ThreadGuard() { reset(); }  // join if joinable

  ThreadGuard(const ThreadGuard&) = delete;
  ThreadGuard& operator=(const ThreadGuard&) = delete;

  ThreadGuard(ThreadGuard&& other) noexcept : t_(std::move(other.t_)) {}
  ThreadGuard& operator=(ThreadGuard&& other) noexcept {
    if (this != &other) {
      reset();                 // join current, then steal
      t_ = std::move(other.t_);
    }
    return *this;
  }

  void join() { if (t_.joinable()) t_.join(); }
  void reset() noexcept;       // join + become empty
private:
  std::thread t_{};
};

Rule of Five: once you define a destructor (or any special member), consider all five — destructor, copy ctor, copy assign, move ctor, move assign. ThreadGuard deletes copy (two guards must not own one thread), defines move (steal + leave empty), and joins on destroy.

Join order

RAII joins on destroy, but you must still flip shutdown flags and wake_all() / notify CVs before guards go out of scope — otherwise join waits forever. MultiSymbolPipeline::run does that, then joins matchers and publisher explicitly.

04

Rule of Zero and unique_ptr<Shard>

Rule of Zero: types that only hold values / standard RAII members need no custom special members — compiler defaults are correct. Prefer this for GatewayOrder, PublishEvent, and plain config structs.

gateway_order.hpp · Rule of Zero
struct GatewayOrder {
  SymbolId symbol_id{0};
  lob::OrderRequest request{};
  std::chrono::steady_clock::time_point enqueued_at{};
  // no custom special members — move/copy as members allow
};

Shard embeds two SpscQueues (mutex + CV → non-copyable, and not safely relocatable while live). That makes Shard itself non-movable, so it cannot live directly in a resizing std::vector<Shard>.

multi_symbol_pipeline.hpp · unique_ptr<Shard>
struct Shard {
  SpscQueue<GatewayOrder, kIngressQueueCapacity> ingress;
  SpscQueue<PublishEvent, kEventQueueCapacity> events;
  lob::MatchingEngine engine;
};

// unique_ptr: Shard is not movable/copyable,
// so it cannot live directly in a resizing std::vector.
std::vector<std::unique_ptr<Shard>> shards_;

for (std::size_t i = 0; i < num_symbols_; ++i) {
  shards_.push_back(std::make_unique<Shard>());
}

Same pattern for matcher guards: std::vector<std::unique_ptr<ThreadGuard>> when you need a growable collection of move-only RAII owners without relying on vector reallocation of the guard type itself during setup.

Decision

unique_ptr for non-movable heap ownership; values for messages. Rejected: forcing Shard to be movable just to sit in a vector. Rejected: shared_ptr<Shard> — exclusive ownership is enough; workers take raw refs into pipeline-owned storage that outlives the threads.

05

SpscQueue<T, N> — type param + NTTP

A class template is a blueprint. T is the payload type; N is a non-type template parameter (NTTP) — a compile-time capacity, not a runtime allocator argument. Instantiating SpscQueue<GatewayOrder, 1024> and SpscQueue<PublishEvent, 1024> yields two concrete types with the same algorithm.

ParamKindRole here
typename T Type GatewayOrder, PublishEvent, …
std::size_t N Non-type Fixed ring size via std::array<T, N>
spsc_queue.hpp · header shape
template <typename T, std::size_t N>
class SpscQueue {
  static_assert(N >= 1, "SpscQueue capacity must be >= 1");
public:
  static constexpr std::size_t capacity() noexcept { return N; }
  bool try_push(T&& item);
  bool try_pop(T& out);
  template <typename StopPred>
  bool pop_wait(T& out, StopPred&& stop);
  void wake_all();
private:
  std::array<T, N> buf_{};
  std::size_t head_{0}, tail_{0}, size_{0};
  mutable std::mutex mu_;
  std::condition_variable cv_not_empty_;
  std::condition_variable cv_not_full_;
};

// Different N → different types (capacity is part of the contract)
SpscQueue<GatewayOrder, 512>  a;
SpscQueue<GatewayOrder, 1024> b;
// a = b;  // ill-formed

T should be move-assignable. Capacity is part of the type contract for v1 — readable, allocator-free ring storage, easy to reason about under overload.

06

Lambdas as thread entry — captures that matter

std::thread accepts any callable. Matcher and publisher entry points in multi_symbol_pipeline.hpp are short lambdas that close over pipeline state and call into run_matcher_worker / run_publisher_multi.

multi_symbol_pipeline.hpp · matcher lambda
ThreadGuard publisher{std::thread([this, event_ptrs] {
  run_publisher_multi(event_ptrs, matchers_left_, wake_, log_,
                      echo_stdout_, &stats_);
})};

std::vector<std::unique_ptr<ThreadGuard>> matchers;
for (std::size_t i = 0; i < num_symbols_; ++i) {
  matchers.push_back(std::make_unique<ThreadGuard>(std::thread([this, i] {
    run_matcher_worker(shards_[i]->ingress, shards_[i]->events,
                       shards_[i]->engine, ingress_done_, matchers_left_,
                       event_drops_, &wake_, &stats_);
  })));
}
CaptureMeansRisk here
[&] All automatic vars by reference Dangles if the lambda outlives the frame; loop index shared
[=] All automatic vars by copy Copies pointers/refs inside objects still shallow; this is a pointer copy
[this, i] Pipeline pointer + index by value Pattern used here — Pipeline / run frame must outlive join
[&, i] Refs default; copy i Usual alternative when closing over many locals by ref
classic loop bug
// BAD: all threads may see i == num_symbols_
for (std::size_t i = 0; i < num_symbols_; ++i) {
  threads.emplace_back([&]{ run(shards_[i]); });  // i by ref!
}

// GOOD: copy the index into the lambda
for (std::size_t i = 0; i < num_symbols_; ++i) {
  threads.emplace_back([this, i]{ run(shards_[i]); });
}

Avoid std::function on the hot path. Type erasure can allocate and always indirection-calls. Matcher → engine → event push stays direct. Optional hooks (test spies, rare stats backends) can use std::function at the edge — not inside every match.

this lifetime

Capturing this (explicitly or via [=]) does not extend the object. Join workers before destroying the pipeline; flip ingress_done_ and wake queues first so loops exit.

07

Pitfalls

✕

shared_ptr “just to be safe” on orders

Hides who may mutate the message. Prefer exclusive moves of GatewayOrder / PublishEvent.

✕

Copying a queue or returning refs into ring slots

Copy is deleted for a reason. Peeking a const T& out of the buffer races with the next push into that slot.

✕

Capturing the loop index by reference

All matchers collide on the same i. Copy the index: [this, i] or [&, i].

✕

Assuming [=] deep-copies the pipeline

It copies the this pointer, not the object. Member lifetime still ends at destruction — join first.

✕

Joinable thread without RAII

An early return or exception that skips join() terminates the process. Own threads with ThreadGuard.

✕

std::function inside every match

Indirect calls and possible allocations add noise on the critical path. Keep type-erased hooks off the book’s hot section.

08

Engineering decisions

TopicChoiceWhere
Order ownership Move value types hop-to-hop gateway_order.hpp, queues, matcher
Queue special members Copy deleted; live queues not relocated spsc_queue.hpp
Thread lifecycle RAII ThreadGuard (Rule of Five) thread_guard.hpp
Message types Rule of Zero PODs / aggregates GatewayOrder, events
Non-movable shards vector<unique_ptr<Shard>> multi_symbol_pipeline.hpp
Queue shape SpscQueue<T, N> NTTP capacity spsc_queue.hpp
Thread entry Lambdas with [this, i]; no hot-path std::function pipeline + matcher_worker.hpp
Decision

Exclusive move hand-off + RAII joins + unique_ptr for non-movable shards + compile-time queue capacity + explicit lambda captures. Rejected: shared ownership of in-flight orders; detached workers; peeking into ring slots; type-erased callables on the matcher critical path.
